Building a Liquid-Cooled Hyperconverged Inference Platform

May 20, 2026 · 8 min read

Running large language models locally requires serious hardware. Over the past year, I've been designing and assembling a custom liquid-cooled homelab optimized specifically for AI inference workloads. This post walks through the architecture decisions, hardware selection, and infrastructure software stack.

Why Build a Local Inference Platform?

Cloud inference APIs are convenient, but they come with latency, cost at scale, and privacy concerns. For serious research and development work, having a dedicated local platform offers advantages that cloud simply cannot match: complete data sovereignty, predictable costs, and the ability to experiment freely without worrying about per-token charges.

Hardware Architecture

The platform is built around a dual-socket workstation chassis with custom liquid cooling loops for both the CPUs and the GPUs. The cooling system is critical — sustained inference workloads generate significant heat, and thermal throttling directly impacts token generation speeds.

Key Components

  • Dual NVIDIA RTX 4090 GPUs with custom water blocks
  • AMD EPYC processor for PCIe lane availability
  • 128GB ECC DDR5 RAM
  • NVMe storage array for model weights and KV cache
  • Custom loop with 360mm radiators per GPU

Software Stack

The software layer is where it all comes together. I chose Proxmox as the hypervisor for its excellent GPU passthrough support and ZFS integration. On top of that, Ollama serves as the primary inference engine, with a custom orchestration layer for load balancing across the two GPUs.

Proxmox + vGPU Configuration

One of the more complex aspects was configuring vGPU passthrough so that multiple VMs can share GPU resources for different model sizes. Smaller models (7B parameters) run on fractional vGPU allocations, while larger models (70B+ parameters) get dedicated GPU access.

Performance Results

After optimization, the platform achieves impressive throughput for local inference. Running Qwen-2.5 72B at Q4_K_M quantization, we see sustained generation speeds that make interactive use practical. The liquid cooling keeps GPU temperatures well within safe operating ranges even under sustained load.

What's Next

The next phase involves adding a third GPU and implementing a proper RAG pipeline with vector storage on the NVMe array. I'm also exploring speculative decoding techniques to improve latency for larger models. Stay tuned for the benchmarking post where I compare model performance in detail.
